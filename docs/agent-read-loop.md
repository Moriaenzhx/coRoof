# 阶段 2：Agent 授权读取循环

2026-11-04 实施规格。按用户修订顺序，统一模型层的开发门槛已通过，先用 Coding Plan 的独立合成验收跑通流程，通用 MaaS 和商用部署验收留在发布前。实现与验收记录如下。

首批仅注册 company.overview、attention.explain、work.investigate、coverage.explain。模型提议下一次读取或带引用的回答；服务端固定映射执行，拒绝额外身份、权限、SQL、URL、代码和写入字段。未实现能力不可执行。

每次运行绑定企业、作者、发起会话和可见工作范围；每次读取、模型返回及恢复均重新校验。运行与步骤通过 Alembic 保存，所有企业引用带复合租户外键。初版使用单轮 HTTP 与浏览器串行推进；当前明确交互查询已改为下述持久提交和服务器执行，浏览器只读取进度。未知模型调用不自动重放。取消立即阻止后续工具执行，但不承诺远端请求撤回或免单。

最多六次模型步骤、固定总期限，继续受日/月 Token、调用和并发额度约束。重复能力与参数且无新信息时停止。网络期间释放数据库锁，记录 pending、完成或 unknown；创建和推进都有幂等边界。读取上下文改变时不继续使用旧聚合或证据。

验收顺序：能力权限与提案拒绝 → PostgreSQL 并发/取消/失权/恢复/升级 → 页面交互及构建 → 使用显式 Coding Plan 配置对同一实现执行真实合成流程。每类失败修正后重新测试；未通过前不进入阶段 3。模型和工具状态不伪装成业务事件，业务更新仍须作者明确确认。

## 当前页面入口（2026-11-05）

底部输入框是统一的工作查询输入入口，事项和伙伴建议只预填问题与上下文，明确发送后才提交 Agent。处理过程和结果显示在居中的非模态浮层中，不锁住页面导航；可手动收起，切页时自动收起，同一企业与身份内的进行中任务不会因切页卸载或重复创建。切换企业、身份或角色会清除旧界面状态，迟到响应不能进入新范围。已明确提交的查询由服务器执行，关闭浏览器不取消；原会话失效、权限或来源变化仍会停止后续执行。

`POST /api/v1/agent/runs/submit` 只接受本人的显式只读请求，在同一事务登记任务与 AgentExecution，返回 202。Celery/Beat 负责持久投递、租约和单步推进，重复投递复用幂等键；浏览器只轮询 `GET /agent/runs/{id}`。刷新时 `GET /agent/runs/active` 最多返回 5 个本人当前仍获授权的 ready/running/interrupted 任务，GET 不触发新步骤或模型调用。中断后的恢复必须明确发起，仍须通过现有权限、版本、期限与调用状态检查，未知已发送调用不能自动重放。0018 迁移不为旧任务回填执行意图。

这一执行意图只继续用户已经请求的一次有界查询，不是自主持续关注授权。按企业目标周期读取、浏览器关闭后主动选择新事务，仍需要 Owner 单独确认 WatchGrant 的范围、期限和额度；交互执行不创建该授权，也不获得业务写入能力。本轮计划见 [Yuxi 对照后的五项改进](yuxi-improvements.md)。

“我的工作 → 最近查询”最多显示本人当前仍获授权的最近 5 次读取任务，不包含后台持续关注。打开历史仅重新读取服务器记录，不创建任务、不推进步骤、不调用模型；历史结果不作为长期对话记忆。查询浮层不再提供第二个输入框、“连续查询”或“快速整理”的模式切换。默认先显示结论、建议下一步或资料原文，依据、其他方案与处理过程按需展开；工作、证据、文档原文及业务确认均使用居中详情对话框，原有确认、幂等和权限边界不变。

老板点击“处理这件事”只准备本人方案。详情先显示建议安排及预填的跟进文字，可展开“修改这个安排”，最后点击“确认这个安排”；未经这次明确确认不产生方案确认效果，不自动通知成员或改写工作状态。过期分析或已变化的依据先重新核对，其他 Owner 不能代替准备者确认。企业概览按“动态全景 → 需要你处理 → 项目进展 → 折叠的处理记录与团队动态”排列；决策经验从个人设置进入。

### 有边界的追问与知识目录

底部输入可接着直接上一轮本人已完成的读取任务提问，也可明确切换新问题。`parent_run_id` 仅用于只读交互任务；最多读取直接父轮及更早两轮，每层须在同一企业、属于本人、绑定同一原有效会话，创建时间在过去 24 小时内，状态为 completed 且有有效回答，不得是后台关注任务。每次读取、推进及模型返回后逐层重新检查当前权限与来源版本；明确指定事项的子任务还须与每个纳入父轮的事项一致。

直接父轮保留有限问题、摘要及少量事项/文档标题，更早两轮只提供各自的短问题和摘要，按由近到远排列；不递归复制父轮已经保存的上下文。序列化后的整体限制仍为 1,800 字节，优先保留直接父轮指代信息，更早摘要可能被进一步缩短。旧回答只帮助理解“这件事”“这份资料”等指代，不成为当前事实或授权依据。任一纳入父轮过期、撤权、会话或版本变化，或发现循环引用时，返回 `parent_context_unavailable`；界面提供“作为新问题发送”，须再次明确点击才创建独立任务，不自动重试模型。当前提示契约为 `agent-read-v10`，提案 Schema 保持 `agent-proposal-v3`。这是最多三轮的有限上下文，不是完整长期对话记忆。

盘点知识使用 `knowledge.list`，具体内容使用 `knowledge.search`。两者都只查当前可见的已发布版本；目录最多展示 20 篇并返回真实总数与截断标记。搜索无匹配时返回当前授权目录，明确“未找到匹配原文”，不推断企业没有资料。模型选定读取后，这类目录结果由服务器直接完成答复，不追加模型轮次复述或重复空检索。文档正文问答仍须引用授权原文；带明确 `work_item_id` 的事项专属任务尚未绑定文档范围，不能直接调用知识读取能力。

明确的资料目录问题、承接有效知识父轮的内容追问使用服务器原文检索路径：在正常任务锁、版本和幂等边界内执行既有授权能力，记录真实步骤与 `knowledge_retrieval` 分析，答复 `mode=retrieval`，不调用模型、不新增模型用量。界面明确标记“原文检索”，最多展示 3 个片段、每段 500 字，不冒充全文或 AI 解读。当前问题优先；检索指代仅使用直接父轮的知识标题，不从更早摘要扩张文档范围，新话题不追加旧文档标题。含风险判断或待确认状态的问法不当成单纯目录读取。当前知识候选采用授权全文检索与 BM25Plus 词项排序，具体范围与质量限制见 [知识库](knowledge.md)。

需要模型判断的 Agent 查询仍需要可用的模型配置，预检失败会保留真实失败状态并提示检查企业 AI 设置或查看已记录工作，不自动降级或启用模型。企业明确设置 `disabled` 时，任务推进预检返回 `model_disabled`，表示服务被暂停；服务配置缺失仍返回 `not_configured`，不再将这两种原因混为一谈。若首次推进即发现这些问题，任务会在第 1 步前停止，不发起模型调用；已保存的历史失败记录保留当时的错误码。

2026-11-05 在本次授权接入前，只读核对发现：此前保存的连接属于另一企业，仍为未测试启用的开发用途连接；当前模拟企业的 AI 已暂停且无企业连接，平台也缺少可调用配置。保存、独立开发验收和企业业务启用是不同状态，连接不会跨企业自动共享。前一轮只完善状态说明，没有变更配置；相关失败记录保留当时事实。

用户随后明确授权将已保存连接用于当前模拟企业的本机测试。部署允许名单仅指定重新绑定目标企业并独立加密的一条连接；原企业配置不改，Owner 仍须先测试、成功后明确启用。仅开发/测试环境、mock 模式及当前 mock 成员、回环 `web_origin` 和精确匹配的连接 Profile 同时成立时，前台 Agent 才可使用这个例外。每次推进和模型返回后的配置复核仍重新检查，不能靠历史验证或旧任务绕过暂停、撤销和权限变化。

后台 `watch_grant_id` 运行不接受该例外，持续关注也不允许选用开发连接；用户显式提交的交互查询由 Worker 继续执行，不因此变为 watch 授权。默认未配置允许名单、非本机和生产环境仍关闭。读取范围、知识库 ACL、六步上限、租户预算与作者确认保持原规则；真实业务和生产验收仍需要适用的通用 MaaS 连接。具体边界见 [企业 AI 管理](ai-management.md#本轮单连接本机测试例外)，本轮运行结果另记入开发验收记录，不从旧合成测试推定成功。

本轮阶段门槛：持久执行 PostgreSQL/Redis 98 项和相关 Web 93 项通过；三轮有限追问补充后，相关 PostgreSQL 100 项通过。覆盖独立 Worker 停止与恢复、重复投递、取消、失权、未知调用不重放，以及父链每层授权、来源版本与总字节限制。这些是本地自动验收，不代表通用 MaaS 或远程 Yuxi 服务已验收；旧框架迁移记录保留如下。
