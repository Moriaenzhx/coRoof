# 企业 AI 管理与多供应商接入

2026-11-04，用户授权在模型层阶段增加账户菜单、企业 AI 用量与配置，并兼容主流 LLM 和商用接入方式。本项不提前实现 Agent、连接器或正式收费系统。

实施与验收顺序：

1. 多协议网关：OpenAI Responses、Chat Completions、Anthropic Messages、Gemini generateContent。按供应商处理鉴权、结构化输出、结束原因和用量；协议测试通过后进入下一项。供应商目录不是已验证模型清单，每个连接需要单独在线测试。
2. 企业管理服务：平台服务 / 企业自带凭据 / 停用；企业隔离、加密凭据、保存—测试—启用、版本检查、停用撤销、审计与额度。PostgreSQL 隔离、并发和迁移测试通过后进入下一项。
3. 账户入口与管理页面：使用概览、AI 服务、预算限制和操作记录。Owner 管理企业配置；其他成员仅查看本人用量；部门负责人不自动获得管理权限。交互和 OpenAPI 类型检查通过后完整回归。

平台服务由部署方配置，企业管理员不能查看或修改共享平台密钥。BYOK 凭据使用部署密钥加密，密文绑定企业与连接；不返回明文，不写日志，不进入前端存储。自定义兼容端点只能由部署方预先允许；企业表单不能指定任意网络目的地。

每条连接保留独立版本和验证状态；编辑使验证失效，启用只接受当前版本已通过的连接。测试只发送固定合成材料，释放事务后请求远端，结束时重新校验会话、角色和版本。测试调用单独标记，仍计入模型调用额度，不能当作客户业务任务。配置审计为追加技术记录，不伪装成 WorkEvent 业务事实。

当前采用不可变连接：更换模型、端点或凭据时创建新连接，测试通过后明确切换，旧连接可保留作为人工回退目标。不做自动跨供应商故障切换。单企业最多 20 条未撤销连接。测试只验证连通性和结构化输出，业务质量需使用独立验收集验证，不能把一个合成探测视为全面模型评测。

### 自助配置与已有凭据可见性

企业所有者通过账户菜单 → 企业 AI 设置 → AI 服务 →「配置自己的 API Key」填写供应商、模型、端点及凭据。保存后立即出现在「已保存的 API 连接」，展示模型、端点、凭据尾号、用途和状态；测试通过后另行确认启用。「更换配置」会预填旧连接参数并清空密钥，新连接启用前保留现有服务。

保存只完成连接登记，测试用于验证当前版本，启用才把它选为当前企业的业务服务；三步不能互相代替。连接、验证状态和启用设置均属于各自企业，切换企业不会复制或共享另一企业的凭据。企业明确暂停模型时，新 Agent 任务返回 `model_disabled`；缺少可用服务配置时仍返回 `not_configured`。仅填写供应商和模型名称不代表平台服务已经可用。

已保存的百炼 Coding Plan 凭据也可登记为企业连接，默认显示「已保存 · 仅开发用途」，支持查看、撤销和「配置业务 API Key」。该用途由服务器根据已验证的不可变端点判定，前端不能自行声明或更改权限。保存不产生远端调用；默认禁止企业连接测试和启用，历史测试通过不会自动获得调用权限。2026-11-05 用户明确授权的单连接本机测试例外见下；正式应用仍需使用相应供应商支持应用用途的凭据。

2026-11-05 核对的[百炼官方接入说明](https://help.aliyun.com/zh/model-studio/more-tools)仍将自定义应用后端和自动化脚本列为 Coding Plan 不支持的工具类型，未列出本机模拟例外。下述开关是用户本轮要求的本机开发测试边界，不代表供应商认可该用途。本文保留的旧独立合成测试记录只说明当时的开发验收结果，不等同于企业连接的“测试通过”状态；通用 MaaS 和正式应用验收仍须使用允许相应用途的连接。

### 本轮单连接本机测试例外

用户明确要求将已保存的测试连接用于当前模拟企业。由运维指定源连接、目标企业和当前有效 Owner，复用服务端导入流程；密钥仅在进程内存中解密，再按目标企业和新连接 ID 独立加密。原企业连接保持原样，追加配置审计记录来源连接 ID，不复制业务事实，也不向其他企业自动共享。重复导入保持幂等。导入只保存，仍须当前企业 Owner 明确测试，测试通过后另行启用。

部署变量 `COROOF_AI_DEVELOPMENT_TEST_CONNECTION_IDS` 默认是空 JSON 数组。本轮仅填写上述目标连接的 ID；前端不能传入或扩大这个允许名单。服务器同时要求 `environment=development/test`、`auth_mode=mock`、`web_origin` 为回环主机，以及精确的百炼供应商、`qwen3.7-plus` 模型和 Coding Plan 端点；测试、启用和交互查询另检查当前成员仍属于该企业且使用 mock 身份。连接继续标为开发用途，界面明确说明仅限本机测试，不能视为商用连接。

只有显式连接合成测试和当前企业的前台 Agent 查询可使用这个例外，仍受当前角色、事项与知识库 ACL、连接版本、预算及确认边界约束。后台持续关注拒绝开发用途连接；其他模型入口不会因允许名单而自动开放。默认未列入名单、非本机部署和生产环境均拒绝；生产预检也拒绝带有非空开发连接允许名单的配置。暂停当前企业模型可停止后续使用，回退保留连接、审计和业务数据；不自动撤销远端已发出的请求。

历史文件必须明确指定企业和当前有效的所有者身份后导入，禁止启动时扫描本机文件或向所有企业共享。部署运维可在配置了同一数据库和服务器加密密钥的环境中运行 `scripts/import_ai_connection.py --organization-id <企业 ID> --actor-id <所有者 Membership ID> --config-file <私有 JSON 文件> --name <显示名称>`，或用 `--config-file -` 从标准输入读取。支持 `provider/model/base_url/api_key/output_mode`；旧 `bailian_coding_plan` 名称映射为百炼目录项。导入复用服务端权限和加密流程，同一输入重复执行只登记一条连接及一条导入审计，不自动测试或切换当前模式。输出不包含密钥。

用量以供应商返回的 Token 为观测值，缺失为 unknown；预算占用包含未完成调用的保守预占，二者分别展示。支持日调用 / 日 Token / 自然月 Token / 并发额度与预警阈值；实际费用、供应商余额与应用额度分别表达。当前没有价格账本与供应商对账，费用显示未知，不宣称金额硬限额或正式计费已上线。

新增数据库结构只通过 Alembic 追加迁移。真实身份、支付账单、密钥运维与生产部署仍按阶段 7 验收，现有 production 阻断保留。

## 协议与当前范围

| 目录项 | 原生协议 | 适配方式 |
| --- | --- | --- |
| OpenAI | Responses | text.format、store=false、输入/输出 Token、截断与拒绝 |
| Anthropic / Claude | Messages | x-api-key、output_config.format、缓存输入用量、Schema 方言转换 |
| Google Gemini | generateContent | x-goog-api-key 请求头、responseJsonSchema、思考 Token 计入输出 |
| 百炼 / Qwen | Chat Completions | enable_thinking=false、max_completion_tokens、Schema / JSON |
| DeepSeek | Chat Completions | JSON 对象、max_tokens、完整 Schema 提示及本地严格校验 |
| 其他兼容服务 | Chat Completions | 经部署方登记的精确 HTTPS 端点、JSON / Schema 模式 |

没有任意请求参数透传、供应商工具自动执行、无边界重试或根据名称猜测模型能力。并非每个供应商的每个模型都支持上述模式：准确模型 ID、地域、账号权限和所需输出模式必须单独测试。当前多供应商通过 HTTP fixture 协议回归，尚未用各家真实凭据完成业务验收。Azure / Bedrock / Vertex 原生签名与云身份、自动模型发现、价格账本、正式发票和扣款、SSO、细分 AI 管理角色均未实现。

协议依据（2026-11-04 复核）：[OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)、[Anthropic Structured Outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)、[Gemini generateContent](https://ai.google.dev/api/generate-content)、[DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/)。适配器处理协议差异，返回结果始终使用原业务契约重新校验。

## 部署配置

`COROOF_AI_SECRET_KEY` 是独立的 Fernet 服务器加密密钥，不是供应商 API Key。通过密钥管理系统注入；本地可保存在 Git/Docker 忽略、权限 0600 的 `infra/.env`。为空时界面仍可查看用量，但禁止保存企业凭据。更换密钥前必须安排旧凭据解密再加密及备份恢复；当前没有自动轮换，直接替换会使旧密文无法使用。

`COROOF_AI_ALLOWED_BASE_URLS` 为 JSON 数组，按完整 HTTPS base URL 允许地域端点或可信企业网关。部署方应只登记可信目的地；连接请求不跟随重定向，不从进程代理环境继承网络设置。平台 API Key 只通过服务器配置注入，永不返回租户界面。平台模式的日调用、日/月 Token、并发上限受部署配置限制，降低部署上限立即生效；BYOK 受企业所设额度及服务端字段上界限制。

`COROOF_AI_DEVELOPMENT_TEST_CONNECTION_IDS` 是独立、默认关闭的本机测试允许名单，不替代端点登记、企业连接测试、Owner 明确启用或服务端身份校验；本轮只授权一个模拟企业的单条连接。生产配置必须保持为空。

追加迁移 `0004_ai_management` 新建三张租户表并扩展 ModelInvocation。升级前备份；迁移测试覆盖已有调用记录及约束保留、降级再升级。界面入口为侧栏账户菜单，包含个人设置、使用概览、企业 AI 服务、预算限制与操作记录。生产阻断不因选择平台服务或 BYOK 而解除。
