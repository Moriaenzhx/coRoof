# 企业系统接入与文件导入

2026-11-07。独立于现有 V1 基线的接入专项。用户确认：老 ERP、CRM 没有接口时也要能通过 Excel 等文件接入；同时覆盖其他常见企业管理软件，优先做通用 Excel / CSV。

## 1. 本 PR 范围与现状

本 PR 首先交付**文件作为企业资料进入知识库**的路径：有界读取 `.xlsx` / `.csv` → 只读内容预览 → 提醒本人当前未编辑原文件的重复上传 → 保存本人草稿 → 本人明确确认发布。预览不落库、不调用模型；保存时重新解析和授权。沿用同一知识库、文档修订和 ACL；不会另建一套“ERP 文档库”。实际支持格式、限制和验收结果见 [知识库说明](knowledge.md#2026-11-07-excel--csv-导入与预览)。

这一阶段不把文件行写成客户、订单、库存或财务台账，不把“成功读取表格”等同于“已接通 ERP”。列映射、业务键去重、更新已有业务对象、业务数据确认与撤销属于后续结构化导入阶段。文件导入也不提供持续同步，来源系统里的后续修改需要重新导入或另行建立连接。

当前外部连接器只有 GitLab、飞书项目的只读离线实现；尚无本专项列出的新供应商适配器。既有实现及真实联调门槛见 [Slice 03](slice03.md)。当前“团队空间”是部门浏览入口，完整 Space 模型、字段权限与空间级 AI 范围仍按 [统一空间设计](department-data-design.md) 落地。

产品支持两种使用方式：已有系统的企业从原系统导入或同步，原系统继续维护权威业务记录；没有系统的小企业以后可直接维护轻量客户、订单与交付记录。复杂会计、税务、库存计价和生产排程复用成熟业务系统，不在此专项重建。

## 2. 接入优先级与软件类别

| 类别 / 优先级 | 首批需要的内容 | 代表产品与已核查的官方路径 | coRoof 的接入边界 |
| --- | --- | --- | --- |
| Excel、CSV、在线表格 / P0 | 老系统导出报表、客户清单、交付计划、规章资料 | [ERPNext Data Export](https://docs.frappe.io/erpnext/data-export) 支持 CSV / Excel 导出；[Microsoft Graph Excel](https://learn.microsoft.com/en-us/graph/api/resources/excel?view=graph-rest-1.0) 提供工作簿、表、区域 API，但不支持 `.xls` | 本 PR 先做文件资料；在线表格连接与结构化台账随后实施，二者都不自动授予文档发布或业务写入权限 |

| 项目与研发管理 / P1 | 项目、任务、问题、责任与状态 | 已有 GitLab / 飞书项目离线适配；[Jira Cloud REST API](https://developer.atlassian.com/cloud/jira/platform/rest/v3/) 提供问题等资源 | 复用现有 SourceRecord / SourceLink / WorkEvent 路径；状态、人员、删除和撤权映射逐平台验收 |
| 财务、报销与票据 / P1（专项权限后） | 报销申请、审批结果、发票资料、已核对收款及来源凭证 | [Frappe HR Expense Claim](https://docs.frappe.io/hr/expense-claim) 描述报销单及处理流程，可结合 Frappe 文档 API；其他财务产品按实际部署核对 | 申请、审批、报销支付、银行到账是不同事实。文件是凭据，不自动记账、核销、开票或支付 |
| 人事与考勤 / P2 | 经授权的部门、在职成员、岗位和协作所需可用信息 | [钉钉开放能力](https://open.dingtalk.com/document/ability/map) 提供考勤、智能人事与组织相关 API | 优先组织同步；人事记录不能直接提升 coRoof 角色。工资、证件、精确打卡位置及健康信息不默认导入或交给 AI |

| 客服与售后 / P2 | 工单、客户问题、处理状态与明确服务期限 | [Zendesk Tickets](https://developer.zendesk.com/api-reference/ticketing/tickets/tickets/) 提供工单 API，另有[账号数据导出](https://support.zendesk.com/hc/en-us/articles/4408886165402-Exporting-ticket-user-or-organization-data-from-your-account) | 公共回复、内部备注、附件分别授权；不因能看到工单就自动联系客户或关闭工单 |
| 电商与订单平台 / P2 | 订单、退款、商品明细、履约状态 | [Shopify orders](https://shopify.dev/docs/api/admin-graphql/latest/queries/orders) 支持订单分页、筛选及更新时点条件；国内平台另按真实商家账号确认 | 一个订单多行明细不能重复计总额；取消、退货、退款分开；不自动发货、退款或修改价格 |
| BI、报表与分析 / P2 | 已批准的指标、期间、数据口径与刷新时间 | [Power BI Execute Queries](https://learn.microsoft.com/en-us/rest/api/power-bi/datasets/execute-queries) 可按权限查询语义模型，要求租户配置及数据集读 / Build 权限 | 复用已定义指标，不将汇总报表伪造成逐单事实；保留过滤条件与覆盖范围，注意部分结果和来源陈旧 |

企业微信、泛微、致远、纷享销客、销售易、北森、易快报、有赞、旺店通、聚水潭、禅道等可进入客户需求候选池。本轮未逐版本核验它们的可用接口，不能显示为“已支持”。选择供应商时记录真实版本、官方文档、测试账号范围和样例导出文件；优先覆盖试点企业实际使用的系统，不同时开发所有品牌。

## 3. 一个入口，两条接入路径

后续统一入口规划：设置中使用“数据与连接”，普通工作页面仍围绕团队、项目和资料，不要求老板学习供应商接口。按权限提供“上传文件”“连接系统”两个动作，并展示最近一次导入 / 同步、来源覆盖与需处理的问题。本 PR 的文件入口仍在知识库“添加资料”，尚未交付新的连接管理界面。真实可用的入口才能出现启用按钮；路线图条目不能伪装成已可连接。

文件路径：选择文件 → 预览内容及目标位置 → 核对共享范围 → 保存草稿 → 明确发布。后续结构化路径增加“列对应什么”和“本次将新增 / 更新哪些记录”两步；支持保存经确认的映射模板，下次只核对变化。界面使用“客户编号、合同金额”等业务语言，复杂配置放在展开项。

API 路径：选择系统与版本 → 授权最小范围 → 测试 → 预览来源对象及分享范围 → 明确启用 → 有界同步。没有 API 的老系统继续走文件路径；客户授权的数据库只读视图、SFTP 或定期投递目录以后单独评估，不默认读取整库，也不把桌面自动操作当作稳定接口。

连接器是来源，知识库是资料，领域对象是业务事实。同一份文件可被团队或项目引用，但仍是同一个文档 ID / 发布版本 / ACL；同一订单可以关联多个空间，不能因此重复计金额。来源链接与空间对象关系需要明确建立，模型不能靠相似名称自动认定为同一客户或订单。

## 4. 文件支持与内容确认

| 文件 | 首批处理 | 后续处理与限制 |
| --- | --- | --- |
| `.xlsx` | 使用 openpyxl 和 defusedxml 有界解析，保留表名及原始行列位置；数字为原始值，日期为 ISO 格式，不复现数字显示格式，公式只作文本 | 隐藏工作表 / 行 / 列 / 名称整份拒绝，因为原文件可下载；宏、外链和嵌入对象拒绝。合并表头不自动映射，列映射后才能写领域对象，不从颜色或排版推断业务状态 |
| `.csv` | 接受 UTF-8、带 BOM 的 UTF-16，尝试 GB18030 并提示核对；识别逗号、分号、制表符，保留原文件行位置与文本编号 | 列数 / 引号不一致或分隔符无法识别时明确失败；不默默丢弃错误行，不删除合法重复行，不把手机号和长单号转浮点数 |
| 旧 `.xls` | 明确提示在原软件另存为 `.xlsx` 或 `.csv`，首批不悄悄按文本读取 | 只有选定解析库并完成独立边界测试后才增加原生支持 |
| PDF、Word、文本 | 复用现有知识资料链路及实际已支持格式 | 报表与合同内容是证据。OCR、扫描件表格、票据字段抽取另行验收，候选字段需要人工核对，不自动形成财务事实 |
| 宏文件、加密文件、压缩包 | 首批明确拒绝，说明可接受格式 | 不执行宏、公式或外部链接；不后台解密，不把文件密码存入连接配置 |

初次上传和预览不调用模型，不执行内容中的指令。预览接口只读，解析前后重查授权。文件摘要只提示当前有权读取、本人创建文档的当前发布版本或本人当前草稿，且提取正文未被编辑；不匹配历史修订或他人文件，不能通过重复提示泄露其他部门文档。文件名不是去重依据；相同内容但共享目的不同由作者明确处理，不偷偷合并 ACL，不删除表内合法重复行。该提示不是台账行去重或业务幂等。

实际限额为文件 4,000,000 字节、XLSX 最多 20 张工作表、表格合计 2,000 行 / 每行 100 列 / 合计 20,000 格、单格 8,000 字符、提取正文 120,000 字符；XLSX 最多 200 个压缩条目、解压声明总大小 8,000,000 字节。解析子进程超时 15 秒。超限明确失败，不能静默截掉一部分再报告成功。公式只作为文本，不计算或采用缓存金额，不访问外部链接。当前不生成错误行下载；后续若增加，需防止导出内容变成可执行公式。

当前保留文件名、原始文件、文件摘要、文档作者 / 修订及发布时间，提取正文包含工作表与原始行列位置。源系统和导出时点尚无专用录入字段，不能从上传时间推断；后续结构化导入补充这些来源字段。上传时间不等于业务发生时间，也不表示记录已更新到今天。表内缺失值保持未知，空白金额不变成 0；金额、币种、含税口径、单位、时区和期间需明确。

## 5. 后续结构化导入契约

结构化导入需要先完成对应领域对象、授权和确认命令。先选一个真实闭环，逐一增加客户、订单、交付登记、收款计划 / 已核对到账；不导入不存在的业务类型，也不为绕过建模把每一行变为 WorkItem。

- **暂存与确认。** ImportBatch / ImportRow 是待核对候选，不进入正式统计、工作提醒或 Agent 事实检索。映射规则、原文件摘要、目标类型、目标范围与基础版本绑定成预览版本，修改任何一项均使旧确认失效。
- **明确变化。** 预览分别列出新增、无变化、拟更新、冲突和错误行。默认错误或冲突阻止确认；允许“只导入有效行”必须单独列明排除行并由用户选择。失败后不能显示整批成功。
- **识别同一对象。** 使用“企业 + 来源数据集 + 稳定外部 ID”识别；没有稳定 ID 时要求选择并校验组合业务键。文件 hash 防止重复提交，业务键处理不同文件中的相同记录；二者不能互相替代。姓名、公司简称或行号不能默认当永久 ID。
- **更新与冲突。** 同键同内容幂等跳过；同键不同内容显示字段差异和版本冲突。来源较旧不能覆盖新记录。客户归属、责任人、部门、订单关联需要显式匹配，不自动创建账号或提升角色。
- **来源权威。** 外部导出快照继续归属于外部来源；用户若选择迁移为 coRoof 原生记录，需预览权威切换及后续同步影响。不得同时允许两边无约束覆盖。重传文件缺少某一行不等于删除该业务对象。
- **事务与审计。** 确认时重查身份、字段权限、候选版本和目标版本；业务变更、WorkEvent、投影与幂等结果同事务。大批次使用有界分块与确定的行结果，不重复记账或重复建单；所有关联带租户复合外键，迁移用 Alembic。
- **撤销与更正。** 未发布草稿可以按现有规则撤回；已经生效的导入以批次记录、版本检查和更正 / 补偿事件处理。被后续业务引用的记录不得直接删除“回滚”；撤回来源时同步使引用与 AI 派生结果失效。coRoof 的撤销不代表撤销源系统业务。

## 6. 权限、AI 与同步可靠性

上传权限、发布权限、接入凭据管理、资料读取、字段读取、AI 使用和外部写回分别授权。现有连接器的部门分享模式不能直接用于财务、人事和客户个人信息。能管理连接不代表可以查看所有导入内容；能进入空间也不代表有工资、合同金额或银行字段权限。

API 和文件最终查询都执行“租户 → 对象 → 字段 → 当前来源版本”校验，计数、搜索、导出、预览及 AI 摘要不能泄露隐藏记录。默认不把整个原始文件发送给模型，模型只能读取当前获授权、已确认、可追溯的内容。资料中的提示文本始终是数据，不能更改系统授权或调用工具。

复用现有加密凭据、来源快照、Outbox、Worker、幂等和恢复结构，优先使用供应商 SDK / 已验证协议适配器。扩展业务类型时保留来源 ID、版本、来源更新时间、抓取时间、水位、删除 / 撤回与错误状态。增量需要重叠窗口或供应商游标；Webhook 需要验签、防重放和去重，并保留定期核对路径。限流、分页、部分成功、凭据轮换、长时间断连及撤权必须可观察。

每次同步都记录实际覆盖范围，未知 / 部分 / 陈旧与完整分开。文件仅提供截至明确时点的快照；API 调用成功也不自动说明覆盖全企业。老板可见的提醒必须能追到当前有权读取的业务记录；无数据时不生成健康结论，无变化不重复提醒。

外部写回放到只读链路稳定后的独立步骤：先展示操作对象和具体差异，取得有权主体的明确确认，再校验版本、权限和幂等。仅收到外部系统成功回执后才显示完成；超时结果未知时先核实，不盲目重试。涉及审批、金额、库存、人事与客户消息的动作不能由“接通系统”或模型建议自动开启。

## 7. 当前 PR 与后续专项的实施与验收顺序

本 PR 仅覆盖 A；B 至 E 是后续独立阶段，需先具备对应领域对象、权限、真实样例和测试授权，不包含在本次“文件导入完成”的交付声明中。

| 阶段 | 交付与依赖 | 通过条件 |
| --- | --- | --- |
| A. 通用文件资料（本 PR 首批） | Excel / CSV 有界解析、预览、本人重复提示、资料草稿及确认发布；复用现有知识库 | 正常与恶意 / 超限样例通过；错误不残留半成品；预览 / 保存不自动发布；重复提示不泄露他人文件；发布、撤权和引用失效沿用知识库测试 |
| B. 结构化导入底座 | 对应领域 schema、权限、ImportBatch / ImportRow、列映射与明确确认 | 错误行 / 重复 / 多工作表 / 金额与日期 / 并发版本冲突逐项通过；确认前无业务事实，重复确认只有一次效果；已有库迁移保留数据 |
| C. 首个 CRM 或 ERP 只读试点 | 以试点账号与已确认数据类型选定一个供应商；新适配器复用共同同步机制 | 真实字段映射、分页、增量、删除、撤权、限流、重复及 Worker 恢复通过；财务字段未经专项授权不可读；离线通过与真实验收分别记录 |
| D. 协同、项目与其他系统 | 按上述目录按需逐个增加，统一空间显示来源，不新增一套信息架构 | 同一对象跨来源不会重复计数；业务关联有依据；团队切换、知识 ACL、移动端、AI 来源与陈旧提示通过 |
| E. 受控写回 | 领域命令、确认、外部幂等 / 对账和审计完备 | 未确认不写；失权 / 版本变化拒绝；重复确认不重复执行；超时未知可核实；源系统审批与业务规则不能被绕开 |

示例验收全用明确标识的合成企业与文件，首批至少包括：重复上传、不同文件名同内容、同业务键变化、空列和长单号、公式 / 外链、超大解压、错误编码、跨企业对象、员工看不到财务资料、确认前撤权、撤回后旧 AI 引用失效。数据库业务并发验收必须使用 PostgreSQL。普通知识资料上传测试不能替代客户 / 订单 / 财务台账测试。

未提供真实外部账号时，先交付离线契约与测试；保持未连接状态，不展示伪造的同步成功。生产上线仍受真实身份、部署、备份恢复及团队试点门槛约束。这个专项的目标是让老板在一个界面理解和推进真实业务，而不是让模型接管所有外部系统。
