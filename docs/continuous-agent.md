# 持续运行的企业 Agent：V1 设计增补

2026-11-04 用户要求：服务持续运行，主动规划企业与团队事务、推动项目、发现有依据的问题，交给老板解决；不能无中生有。本文件记录 V1 的设计、实现与逐步验收，**不是生产上线或真实团队试点通过的声明**。第 8 阶段复用问答、人工确认图和只读同步基础，已实现主动关注循环；具体测试与仍待外部验证的边界见文末。

## 产品行为

服务无需保持浏览器打开。Owner 在企业设置中启用持续关注，选定企业/部门/项目、关注目标、节奏、额度与接收范围。企业后台持续接收已确认事件、授权来源的同步完成事件以及定时触发，必要时读取更多获授权资料。先核对数据覆盖与变化，再判断是否需要分析、准备推进方案或请人核实。

例如，“交付节点到了，且成员明确报告客户资料缺失”可以生成有引用的协调建议和待老板决定的选项；只看到 GitLab 议题 opened，不能推断“延期”“团队效率下降”或需要老板催促。源系统同步失败时优先显示“资料更新失败”，不据旧内容新增经营风险。客户取消、收款、实际交付等没有对应事实时始终未知。

规划基于用户确认的目标、现有工作与依赖、已提供的约束。缺少目标、资源容量、依赖关系或截止时间时，可以提出补充信息的问题及带假设的草案，不能自动补造预算、人员能力、工时或项目承诺。当前领域模型没有完整依赖图和资源容量；在新增已授权且经测试的字段前，不宣称具备关键路径计算或资源排产能力。

## 运行方式与框架分工

```text
已确认 WorkEvent / 授权同步完成 / 到期的定时关注
 -> PostgreSQL 事务 Outbox（不在网络调用中持有事务锁）
 -> Celery Worker；Beat 唤醒到期策略与未投递消息
 -> 当前租户、持续关注授权、范围、额度与来源版本检查
 -> 规则筛选变化、合并重复事件、检索获授权的事实/知识/结果
 -> LangGraph 有界执行图 + 官方 PostgreSQL checkpoint
 -> LangChain 统一模型调用（仅在有待分析内容时）
 -> 引用与新鲜度校验
 -> 无变化：静默 / 资料不足：待核实 / 有依据：方案或老板待办
 -> 人工确认（interrupt / Command） -> 领域服务事务 -> 实际结果跟进
```

“服务持续运行”指后台进程和持久化调度持续可用；每轮任务有明确结束条件，不让 LLM 空转，不创建无上限的 while 循环。沿用 Celery、Redis、Tenacity、LangGraph 与现有领域服务，不另造队列、工作流或检查点引擎。API/Worker 为同一 Python 模块化单体的独立部署进程，暂不拆新微服务、不修改 Go/spec 协议。

触发语义必须可恢复：业务事件和 outbox 同事务；任务使用企业 + 策略版本 + 事件范围/定时窗口的去重键。租约过期后重派，旧 Worker 使用版本隔离；租户内合并并发变化。持久化 next_due_at，重启后合并错过的窗口，避免补跑大量重复提醒。模型请求结果未知时保留用量占用，按既有规则核对/恢复，不盲目重复计费调用。

## 授权、事实与动作

| 可自主执行的行为 | 必须满足的边界 |
| --- | --- |
| 查看、查询、分析、提出待核实问题 | 使用 Owner 明确授予的持续关注范围，服务端每轮重新校验；有期限、可暂停、可撤销 |
| 组织推进方案、协调草案、待确认决策 | 每项事实绑定来源 ID/版本/来源时间；假设、建议、未知分别标识；草案不改变真实项目状态 |
| 在产品内生成老板关注待办 | 仅对新的可行动问题、风险升级、到达明确跟进时间生成；相同事实和同一策略不重复打扰 |
| 修改计划、负责人、承诺日期、确认决策或实际结果 | V1 继续绑定具体参数、版本、有效期与有权主体的明确确认；不能代确认员工更新 |
| 外部写入、消息通知与自动执行 | V1 连接器只读，没有这些能力；后续须独立实现、显式授权目的地与动作，不能由持续关注开关顺带开启 |

后台授权是独立的、有范围和期限的授权记录，不借用永久 Owner 会话。组织、授予人、策略、目标与派生结果均有租户复合外键。授予人失权、Owner 变更、来源撤回或文档 ACL 变化时，取消相关排队/等待任务，清理可见结果与检索缓存，已发起调用返回后也须重新检查再展示。

来源中的指令、提示注入、未确认草稿和模型自己生成的摘要不能成为企业事实。引用验证不仅检查文字能否找到，还检查它是否支持所声称的结论；不支持的原因归因变成待核实，不转成确定风险。历史“问题”若证据已消失，应标记失效，而非自动视为已解决。只有确认结果或可靠源事实支持时才能标记完成。

## 领域记录与界面

- `AgentWatchPolicy`：租户、授权人、范围、用户确认的目标、触发条件/节奏、时区、预算、授权期限、暂停状态与版本。所有配置改变审计。
- `AgentWatchRun`：触发来源、策略版本、已读取的事件窗口、数据覆盖、来源版本、检查点关联、执行/等待/停止原因、用量。运行记录不保存隐藏推理。
- `AttentionItem` / `PlanProposal`：依据、条件与不确定性、影响范围、候选动作、具体待老板决定的问题、关联事项、去重键、状态及下次跟进时间。它们是建议/待办，不替代 WorkEvent 事实。
- `AgentWatchGrant`：有权授予者、范围、允许的只读能力、有效期与撤销记录。图状态、模型参数和客户端角色均不能作为授权依据。

上述为设计名；当前 0012–0016 已建立 WatchPolicy/Grant/Run 与 AttentionItem/Review。推进方案复用 AgentRun 和 Decision，不另建独立 PlanProposal。确认图与使用量仍复用原有记录，不并行维护第二套工作系统。

老板主页保留安静的企业全景，增加“需要你处理”和“Agent 正在关注”：展示最近检查时间、范围覆盖、未接入来源、待核实事项和可审阅方案。每条待办说明为何现在出现、依据和更新时间、需要哪项决定、忽略/稍后处理的影响。允许暂缓、取消、纠正、查看历史及暂停关注。设置页提供运行开关、授权范围、节奏、模型/费用额度、提醒与执行记录。

没有新变化时静默；没有资料时展示覆盖缺口，不用示例企业数据填充、不报“运行正常”。定时提醒只是系统待办，不能替代实际工作进展。先提供产品内待办，外部投递待真实渠道与显式授权完成后另行验收。

## 各阶段的接入与门槛

| 阶段 | 持续 Agent 所需交付 | 必须通过的测试 |
| --- | --- | --- |
| 4 只读连接器 | 来源时间、原始记录、稳定映射、撤权隐藏、持久化同步任务；同步结果可作为后续触发事实 | 重复/乱序/部分同步不编造进展；失权隐藏；真实联调单列 |
| 5 企业知识库 | 文档版本、ACL、删除与索引失效；供执行图按范围检索 | 撤回文档不可继续出现在新结论/派生待办中；资料注入不能修改策略 |
| 6 经验与偏好 | 经确认目标/偏好、实际结果和适用条件；建议优先级可解释 | 不把推测存成经验，不自动确认偏好，不以讨好老板替代事实 |
| 7 身份与部署 | 服务授权、后台进程健康、持久化调度、租约恢复、预算、日志与停机控制 | 浏览器关闭仍运行；重启不丢任务、不重复写入；授权到期立即失效 |
| 8 主动规划与试点 | 关注策略、持续执行图、方案/待办、确认/暂缓/纠正、结果跟进和页面 | 以下运行验收全部通过，再进行真实团队试点 |

第 8 阶段按“策略授权 → 事件/定时触发 → 自主查询分析 → 方案/待办 → 确认/跟进 → 故障与成本验收”逐步推进，每步测试通过才进入下一步，复用阶段 2–3 的图与确认领域服务。

验收至少包括：无数据不产生虚构事务；无变化不反复计费或提醒；同一问题多次触发只有一个有效待办；问题升级可解释；撤权/策略修改后旧任务不展示、不写入；等待中事实改变须重新审阅；缺资料与真实风险分开；无确认不分配任务/发消息；确认重试一次效果；来源更新能继续规划；实际结果未知保持未知；多租户公平调度与费用上限；停止策略能终止后续执行；进程重启和重复投递可恢复；模型失败显示真实降级状态。

## 第 8 阶段实施顺序（2026-11-04）

阶段 7 离线开发门槛已通过。第 8 阶段按以下六个内部门槛推进，每步定向测试通过才接下一步：

1. Owner 明确确认关注目标、企业/部门/项目范围、节奏、日分析轮数和授权期限；独立可撤销 Grant，版本与幂等，退出浏览器不等于撤销后台授权。
2. 确认业务事件事务内唤醒、到期定时补偿、Celery 投递/租约/去重与公平处理；断网或停机恢复合并窗口。
3. 先核对范围、来源和变化，按事项复用 LangGraph 读取执行图、LangChain 网关和现有预算；后台任务用 Grant 校验，不能持有永久浏览器会话。每个模型执行图只读取选中的事项，部门/项目范围在选择和每步授权时再次核对。未知模型结果不自动重放。
4. 基于规则事实和严格引用生成去重关注项、推进方案及明确跟进待办；资料缺口与经营风险分开，来源失效不标为问题已解决；无变化不重复调用模型。
5. 页面提供启停/范围/授权期限、运行记录、待核实/待处理、暂缓/忽略/纠正以及复用现有人工决策确认。V1 先提供逐事项推进方案；没有依赖/容量事实时不提供虚构排产或跨项目承诺。
6. PostgreSQL 并发、进程重启、预算与多租户、合成端到端及完整回归；最后独立记录真实团队与外部服务发布验收。

策略授权与待办属于控制/建议记录，不写成真实业务进展；确认工作状态与实际结果仍走原 WorkEvent 事务。暂停或修改策略会撤销旧 Grant，并使旧运行/方案不可见。默认不发送外部消息、不调用只读连接器以外的写操作，也不代员工确认更新。
