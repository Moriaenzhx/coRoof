# 阶段 5：企业知识库（实施与验收契约）

承接阶段 4 离线开发门槛，按八阶段目标实施。当前文档先定义范围，验收结果另行追加；未测试的功能不算交付。

提供企业文档列表、纯文本/Markdown 编辑与 TXT/MD/PDF/DOCX/XLSX/CSV 导入。文件由成熟解析库在限时子进程中解析；先预览提取内容，再保存作者草稿，原文件与提取文本同租户保存。扫描 PDF、加密文件、宏、超限或无法提取内容均明确拒绝，不虚构 OCR 结果。草稿经作者明确确认后发布并切分/建立索引，未发布内容不进入 Agent。

文档可见范围：私有（作者）、本部门、全企业或指定成员。全企业分享仅 Owner；部门分享须在当前部门（Owner 可选本企业部门），指定成员由当前成员目录权限限制。Owner 不自动绕过私有文档 ACL。编辑由作者或有可见权限的 Owner 管理；草稿确认永远限草稿作者。发布、权限修改、撤回与删除检查版本/幂等，追加租户 WorkEvent；文档事件与事项事件通过明确目标外键区分，不能为知识库虚构工作事项。

LangChain RecursiveCharacterTextSplitter 维护片段及位置；jieba 处理中文检索词；生产 PostgreSQL 使用 GIN 全文索引，SQLite 仅作为辅助验收以 FTS5 实现相同授权语义。检索在租户/ACL/当前发布版本范围内召回候选，再用成熟 `rank-bm25` 的 BM25Plus 做词项排序；不可见文档不进入候选或排序统计。固定数据库基础顺序前 500 个片段重排，其余匹配按原顺序接续，完整总数不裁断，各页使用同一候选头部，避免重排造成重复或遗漏。候选只加载片段和引用元数据，不重复加载完整修订正文或原文件。超过排序范围时返回说明。当前没有 Embedding、模型 Rerank 或向量索引，不宣称具备语义召回或向量混合检索。可追溯引用包含文档、版本、片段、原文及来源时间，支持查看原文/原文件。

现有 LangGraph Agent 提供 `knowledge.search` 原文检索与 `knowledge.list` 目录读取；回答将文档原文与工作事实建议分别表达，不能将制度内容当成实际执行记录。V1 文档问答采用选段式回答：模型选择相关片段及逐字引文，服务器核对片段 ID 和原文位置，界面展示标题、版本、发布时间及全文入口，不额外生成无法机械核验的制度解读。提示注入不授予新能力。复用统一 LangChain 模型层、企业额度、步骤/时间上限及取消；明确目录问题与有效知识上下文中的内容追问可通过服务器直接检索，显示“原文检索 · 未调用模型”；知识库也保留手动原文检索。需要推理的问题仍依赖可用模型，不能将原文读取伪装成 AI 解读。

“有哪些资料”等目录问题读取当前租户、ACL 和已发布版本范围，按发布时间排列，最多展示 20 篇，返回真实总数与是否截断。具体检索最多向 Agent 返回 3 个相关片段；没有匹配时返回同一权限范围的真实目录，分别说明“未找到匹配原文”和“当前权限内暂无已发布文档”，不能把未命中说成企业没有资料。明确目录意图直接读取，不使用模型选择已明确的动作；其他问答中由模型选定读取后，目录和空检索答复也由服务器直接完成，不再花下一轮模型调用复述目录。目录是可见资料清单，不代表正文解读或制度已执行。

文档列表与引用详情都保留员工入口，按企业共享、本部门、指定本人和本人私有资料的实际 ACL 过滤。点击文档或引用时在居中详情中重新读取获授权版本，原文不依赖浏览器缓存片段。问答默认显示相关原文或目录，完整依据与处理过程按需展开。

2026-11-06 查阅与整理入口分开：默认“查资料”仅列已发布版本，按全部资料、全员共享、部门资料、指定共享、仅自己筛选；“整理资料”提供我的草稿、我创建的、已撤回。类别对应当前真实共享范围，不把缺少分类的数据编造成制度、财务或人事目录。添加资料先选择导入或编写，再保存草稿，发布仍需要草稿作者确认；共享设置按需展开。资料提问统一预填全局输入框，不弹出第二个查询抽屉，也不自动发送。

`GET /knowledge/documents` 保留 `view=all` 的兼容默认，新增 `published`、`my_drafts`、`mine`、`my_withdrawn`，以及可选 `visibility` 和字面标题查询 `q`（最多 200 字）。所有条件在 `access.scope` 之后、统计和分页之前执行；我的草稿按当前修订作者筛选，并使用该草稿标题，正式查阅保持已发布标题。`GET /knowledge/search` 可按同一 `visibility` 限定已授权已发布候选，保留原排序及分页语义。前端分页绑定已提交的查询和范围，切换视图/企业/成员会丢弃迟到结果，文件读取期间离开原范围不会继续发起旧身份导入。本轮不涉及数据库迁移。

知识追问可以使用直接上一轮已完成查询的少量标题帮助检索。会话上下文最多包括直接父轮及更早两轮，总计 1,800 字节，每层都必须属于同企业、本人和原有效会话，创建未满 24 小时且当前权限与版本仍有效；只取每层自己的有限摘要，不递归复制旧上下文。知识检索指代只用直接父轮的标题，更早摘要不扩张资料范围。明确内容追问使用服务器原文读取，不新增模型调用；每段最多 500 字、最多 3 个相关片段，不冒充全文。标题不会授予文档权限，检索仍读取当前发布版本；任一纳入父轮失效时要求明确作为新问题发送。完整限制见 [读取循环](agent-read-loop.md#有边界的追问与知识目录)。

发布新版本、修改 ACL、撤回或删除使依赖的 Agent 结果失效；模型调用前后重新检查文档可见性与版本。删除会清除修订正文、原文件、片段与索引，并清除依赖运行的内容缓存；保留不含正文的事件/审计。LangGraph 检查点只保存执行路由和引用标识，不复制文档正文/模型引文。外部检索材料不能修改系统指令。

门槛：中英文召回与引用、未发布隔离、两租户/私有/部门/成员 ACL、草稿作者确认、发布与编辑版本竞争、重复确认一次效果、文件格式与限额、旧版本和删除/撤权传播、调用中撤权、无资料/伪造引用/提示注入、实际 LangGraph 执行、PostgreSQL 并发与旧库迁移；之后跑全栈回归、开发模型合成验收和本地页面检查。真实企业文档不发送到开发测试模型。

实现使用 [LangChain 文本切分](https://docs.langchain.com/oss/python/integrations/splitters/recursive_text_splitter)、[PostgreSQL 全文检索](https://www.postgresql.org/docs/16/textsearch-tables.html)、[jieba](https://github.com/fxsjy/jieba)、[rank-bm25](https://github.com/dorianbrown/rank_bm25)、python-docx 和 [pypdf 文本提取](https://pypdf.readthedocs.io/en/stable/user/extract-text.html)；XLSX 解析复用 openpyxl 与 defusedxml。PDF 解析在独立进程中限制解压输出、页数、CPU 和运行时间；DOCX 限制解压大小和条目数，并用 `iter_inner_content` 保留正文段落与表格的原顺序，不把所有表格移到段落末尾。原文引用定位是提取文本的字符位置，不伪装成 PDF 原始页码；表格另在正文中保留原始工作表、行号和列位置。文件保存在租户修订记录中，单份最多 4 MB / 12 万字符；不支持大文件存储或 OCR。

新增迁移 `0009_knowledge`：文档、修订、读者、片段、Agent 引用依赖，以及 WorkEvent 的文档目标；原事项事件保留。PostgreSQL GIN 与 SQLite FTS5 由迁移管理，不在启动时创建。含文档数据时禁止直接降级丢弃，需要单独的数据迁移方案。

可见性变化与删除使用短事务：锁定企业命令和文档，等待在途读取事务结束，再清理依赖的 AgentRun / AgentStep / AnalysisRun；组织和文档使用 PostgreSQL NO KEY UPDATE，允许已有读取完成复合外键写入，避免撤权与读取相互等待。调用中的结果返回后重新校验范围；已读到浏览器或发送给供应商的内容无法追溯收回，但服务器不再提供失效结果。知识问答只对全局读取开放，具体事项任务尚未建立文档绑定，不扩大其范围。

## 2026-11-07 Excel / CSV 导入与预览

本次是 [企业系统接入专项](enterprise-integrations.md) 的首批文件资料能力。老 ERP / CRM 导出的表格可以作为知识资料核对、保存和发布；文件行尚不形成客户、订单、库存或财务台账，也不代表已接通源系统。列映射、业务键去重、差异更新和台账撤销仍属后续阶段。

导入界面使用“选择文件 → 预览 → 保存草稿 → 作者确认发布”。预览展示实际提取正文，文件、共享范围或身份变化后需要重新核对。`POST /knowledge/import/preview` 在解析前后检查当前租户及共享权限，只返回文件名、文件摘要、提取内容和可见的本人重复提示；不保存文档、修订、原文件或 WorkEvent，不调用模型。保存仍走独立导入请求，重新解析与授权；预览不是发布授权，也不绕过现有版本、幂等和草稿作者确认规则。

重复提示按文件字节摘要查找当前有权读取、本人创建的文档，仅匹配当前发布版本或本人当前草稿中尚未手工修改的提取原文。过期修订、已编辑提取内容、他人文档及失去权限的文档不参与提示。相同文件名不代表相同文件；提示允许作者明确继续创建资料，不合并共享范围。它不是业务记录去重，不能删除表内合法的重复行，也不保证不同文件中的同一订单只导入一次。

| 格式 | 当前实际行为 |
| --- | --- |
| XLSX | openpyxl 只读解析，defusedxml 检查 XML；保留工作表名、原始行号和列位置。数字显示原始值，日期显示 ISO 格式，不复现货币、百分比或前导零等数字显示格式；需要保留的长单号应在原表中存为文本。公式只展示为标记后的公式文本，不求值，也不把缓存结果当作最新金额。空白保持空白，不补为零。 |
| CSV | 接受 UTF-8（含 BOM）、带 BOM 的 UTF-16，并尝试 GB18030；GB18030 结果提示核对中文。识别逗号、分号、制表符，保留文本编号及原文件行位置，含换行的记录保留原始行区间。列数不一致、引号错误或无法识别的分隔符明确失败，不猜测业务列含义。 |
| 旧 XLS | 明确提示在原软件另存为 XLSX 或 CSV；不按文本伪装读取。 |

XLSX 发现隐藏工作表、隐藏行列或隐藏名称时拒绝整份文件，要求另存一份可共享副本；原因是已发布资料可下载原文件，只在提取正文中省略隐藏内容不足以隔离信息。宏、ActiveX、嵌入对象、外部链接及加密内容同样拒绝，不执行或访问外部内容。公式文本、来源文件和错误不能成为系统指令。解析失败只返回固定错误说明，不返回可能含源文件内容的解析堆栈。

| 限制 | 上限与失败处理 |
| --- | --- |
| 上传与正文 | 文件非空且最多 4,000,000 字节；提取正文最多 120,000 字符，单格最多 8,000 字符。 |
| 表格范围 | XLSX 最多 20 张工作表；总计最多 2,000 行、每行最多 100 列、总计最多 20,000 个单元格。XLSX 同时检查原始坐标，不能用伪造维度绕过限额；CSV 按非空记录计行，保留合法重复记录。 |
| XLSX 容器 | 最多 200 个压缩条目、解压声明总大小最多 8,000,000 字节，受子进程资源和超时限制。 |
| 执行 | 最多两个并行解析，单次子进程超时 15 秒、CPU 上限 10 秒；超限、忙碌或解析失败明确报错，不将截断结果保存为成功资料。 |

本轮无数据库迁移；OpenAPI 同步预览 DTO，现有文档 ACL、发布索引、原文件下载、撤权与引用失效机制继续生效。保存前不把预览当成企业事实，发布后也只将表格视为可引用的来源资料。上传时间不是业务发生时间；源系统数据变化后需要重新导入。
