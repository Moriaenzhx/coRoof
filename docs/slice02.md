# Slice 02：依据问答、规则提示与决策记录

日期：2026-11-03。延续白色主区域、窄灰侧栏、海军蓝操作色和克制的状态色。保留 Slice 01 已有修改和用户数据；没有进入连接器或长期偏好记忆阶段。

## 使用流程

1. 在统一的底部输入框明确发送问题，居中的非模态浮层展示处理状态与结果；工作详情的“询问这项工作”和关注提示只预填问题、带入事项上下文。
2. 发送问题后，回答展示模式、覆盖数量、来源时间、原始依据和处理路径。打开入口本身不会调用模型；切页会收起浮层，同一企业与身份内的处理状态继续保留，可展开查看。
3. 老板点击“准备决策”，手动选择方案、编辑处理内容、填写跟进安排，再明确确认。保存草案不等于确认；确认方案不表示工作完成。
4. 老板在“我的工作 → 我的决策与跟进”处理本人待办，查阅当时的事实、解释、选择和时间，追加实际结果及证据引用。“企业概览”可展开企业决策记录，项目详情可展开项目决策记录；两处保留企业所有者权限。结果是追加记录，不覆盖历史。
5. “我的工作 → 最近查询”最多展示本人仍获授权的最近 5 次查询，不含后台持续关注。打开历史只读取记录，不推进任务或重新调用模型。

当前界面已按后续体验要求移除顶栏：企业切换位于“账户菜单 → 个人设置”，身份标记保留在账户入口与设置；首页默认展开动态全景；可拖动小人浮于右下，文本输入固定在底部居中。侧栏保留品牌、导航与账号。具体交互和最新验收见 [开发说明](v1-development.md#标题伙伴与文本入口)。

查询使用居中浮层，不再占用右侧业务抽屉；证据查看、工作草稿和决策确认继续在详情抽屉中完成。浮层内没有第二个问题输入框，也不提供“连续查询 / 快速整理”切换。员工可进入“我的工作”和按文档权限过滤的“企业知识库”；工作问答接口对员工同样实施本人事项范围，知识检索另遵循文档 ACL。

## 当前规则与真实边界

| 类型 | 触发条件 | 表达 |
| --- | --- | --- |
| 明确支持需求 | 非终态且 needs_support=true | 琥珀色支持提示 |
| 逾期未完成 | 非终态，截止时间早于当前时间 | 红色逾期提示 |
| 临近截止且阻塞 | 非终态，有支持需求，距截止不超过两天 | 琥珀色提示；当前以已记录的事项截止时间作为节点 |
| 数据陈旧 | 非终态，七天未更新工作事实 | 灰色时钟；不判断员工是否工作 |

阈值在 `intelligence/signals.py`，规则版本为 `signals-v1`。工作事件提交与规则投影在同一事务执行；读取信号列表或提问会重新评估时间规则。没有后台定时扫描或通知推送。完成/取消的工作不保留有效告警，历史信号不删除。

EvidenceSnapshot 固定事项版本、确认后的字段、最近业务事件摘要及其来源 ID/时间。外部文本只当作资料；原文与确认字段冲突时，以已确认字段为事实。历史快照读取会标记当前事项是否已有更新。没有数据不推断正常，没有计算企业健康分。

原有单轮 `/ai/ask` 每次独立查询当前权限内最多 20 项工作，优先包含触发提示的工作，最多给出 5 项建议，并显示本次与授权总数。当前页面统一使用 [Agent 授权读取循环](agent-read-loop.md)，历史入口位于“我的工作 → 最近查询”，不将旧查询自动作为长期对话记忆输入模型。知识库读取按后续阶段的文档 ACL 单独授权。

## 模型配置与降级

当前页面的 Agent 查询需要已启用且可用的模型服务。配置预检失败时显示实际错误及处理入口，不自动调用单轮 `/ai/ask` 或伪装成成功的规则回答。单轮接口仍保留原有模型优先与规则降级行为，因此不能将它当作保证不调用模型的专用入口。本轮没有增加后端模式参数或改变模型配置。模拟星桥企业当前暂停 AI 且无企业连接，平台预检也未通过；其 `0/6 · not_configured` 表示尚未进入第 1 步，并非模型已经运行六步后失败。

后续模型层阶段 1 已将本节交付时的适配器迁移到统一 Gateway，增加百炼专用配置、限额与调用审计；下面保留 Slice 02 的原始配置与历史验收。当前配置、真实联调命令和剩余门槛见 [V1.0 交付记录](v1-delivery.md)。

默认 `COROOF_AI_PROVIDER=rules`，界面明确显示“规则整理 · 非 AI”。规则只按已有状态给固定的处理参考，不宣称理解任意问题。员工更新草稿也继续使用原有规则 Provider。

可选服务端适配器使用支持 Chat Completions 结构化 JSON Schema 的端点，配置在本地环境文件（例如忽略的 `infra/.env`）：

```dotenv
COROOF_AI_PROVIDER=chat_completions
COROOF_AI_BASE_URL=https://your-provider.example/v1
COROOF_AI_MODEL=your-supported-model
COROOF_AI_API_KEY=
```

复制 `infra/.env.example` 为本地配置文件后自行填入供应商和密钥，运行：

```sh
docker compose --env-file infra/.env -f infra/compose.yaml up --build -d --wait
```

凭据仅供 API 后端使用，不能放入 `NEXT_PUBLIC_*`。URL 必须 HTTPS（本机调试例外），不允许 URL 内含凭据。没有自动搜寻密钥。只有显式完整配置才调用该端点；请求只含当前授权范围的有限摘要、问题和信号。模型适配器不携带执行工具，不重定向、不自动重试、不记录完整原始提示，发送 `store:false`。

模型需要满足 Pydantic 结构、提供允许的证据 ID 和可逐字匹配的引用；拒绝错误引用、明确的数字指标/执行宣称等输出。事实统计与处理方案目录由服务端产生。超时、拒绝、截断、Schema 或引用检查失败会返回规则结果并标明失败降级，审计保留状态。模型散文建议仍需要人工核对；这些检查不构成对所有幻觉的保证。

协议依据：[OpenAI Structured Outputs 文档](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat)。未使用真实密钥进行在线验收；本轮用 MockTransport 验证请求格式和成功/错误响应，不能视为任意兼容供应商都已验证。

## 一致性与迁移

- 迁移 `0002_slice02` 追加四张业务表并扩展 AnalysisRun；所有业务引用使用租户复合外键。没有重建已有业务表或清空数据。
- 模型调用前释放工作行锁。准备与确认重新锁事项，校验当前角色、工作版本、整组信号版本、分析/方案三十分钟有效期；冲突时保留输入并提供重新核对入口。
- 仅 Owner 能准备、读取、确认决策和记录结果。准备只接受本人问答结果。证据和模型上下文使用与普通工作接口相同的当前授权范围，移交后旧负责人失去读取权限。
- 相同请求稳定重放；并发确认只写一条事件。不同内容不能覆盖同一幂等请求，确认后的选择不能覆盖修改。
- 业务事件与审计同事务追加；决策不会自动改变 WorkItem 状态、解除支持需求或操作外部系统。
- 既有库升级前做备份；已产生 Slice 02 数据后不支持无损降级，回退应恢复升级前备份到独立实例再切换，不能直接对有数据的库执行 downgrade。
